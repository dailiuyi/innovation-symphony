# Demo 范围、上下文接口草案与检查清单

本文描述 `innovation-view` 当前只读 Demo 的可见行为和内部数据读取边界。接口随实现演进，**不是 Symphony 的稳定或公开契约**；整合到产品前，应由稳定 API 和权限模型重新定义。

## 用途与边界

看板从本机可读的 Symphony 运行时产物中汇总任务、检查证据和 Codex 会话，供研发查看进展与上下文。它不控制 runtime，不创建或重试任务，不编辑已下发 Prompt，任务配置保持冻结；GH-16 仅新增受控仓库默认模型管理，通过 Elixir 授权并持久化，不部署或合并代码。复制、深链接和摘要下载只作用于浏览器端。

当前界面包括：

- **任务看板：**“需关注、进行中、待人审、已交付”四列与状态统计。任务搜索覆盖标题、Issue、仓库和关联 Agent 角色；可仅看需关注任务，也可切换看板/紧凑列表。筛选和布局偏好保存在当前浏览器本地。
- **任务详情：**卡片打开轮次、回执、检查证据和 PR 信息；任务可通过 `#/story/<story-id>` 深链接打开。有控制器轮次的回执按真实轮次与尝试记录关联会话，编码或 Review 重试不增加轮次；无法关联的会话单独标明归属未记录。每轮默认展示最新 Review，此前的重试与重审记录折叠保留。审查协议校验失败与有效的 Review 打回分别展示，原始会话意见不能代替控制器接受的结论。旧回执没有轮次记录时才按编码顺序作估计归类。
- **Agent：**会话按发生时间排序，默认最近优先，也可改为旧到新；角色可筛选，搜索覆盖角色、会话 ID、Issue、仓库、运行时、模型、指令和最近输出等已采集文本。
- **Agent 上下文：**原生侧栏分为概览和会话记录。概览提供关联任务、下发指令、最近可见输出、源模型和会话来源；内部接口还带模型及工作目录证据字段。记录页按类型筛选、搜索并分页。打开后保持当前采集快照，不随后台轮询替换正在阅读的页面；点击“重新读取”才加载较新的内容。可以复制指令、复制 `#/agents/<session-id>` 深链接、下载 Markdown 摘要，或通过“完整记录”入口打开旧版 `context-<id>.html`。
- **外观与窄屏：**支持亮色/暗色主题和窄屏布局。没有发现运行目录时，状态栏显示“未发现运行目录”，看板各列显示空态；运行状态分别显示服务断开、运行时采集失败和数据过期。发生断联或采集失败时保留最近一次成功快照供查看。

每个 Agent 对应一次 Codex 会话，不代表一个仍在工作的进程。最近输出也可能是过程消息，不能单独证明任务完成。未知字段表示没有采集到可信值，**未知不等于 0**；只有明确采集到的零值才表示零。

## 本机与局域网安全

旧只读模式 HTTP 服务绑定 `0.0.0.0`，任务展示未新增多用户认证。GH-16 模型管理启用时 View 强制绑定 loopback，配置管理的读写需管理员令牌，并校验来源和仓库范围；获准内网代理仍须访问限制，见 [方案](../../docs/VIEW_MODEL_SETTINGS.md)。本机和局域网使用者因此都可能读取看板与会话上下文。rollout 可能含内部代码、命令、路径或其他敏感内容；应只在受信任的本机/局域网运行，并用主机防火墙限制可访问范围。

产品化前至少要设计并实现身份认证与授权、按仓库/会话的权限边界、敏感信息脱敏、数据保留与删除策略，以及网络部署安全。当前 Demo 没有实现这些控制。

## 只读 HTTP 接口草案

以下端点是当前实现细节，调用方不应把它们视为稳定兼容承诺：

| 方法与路径 | 当前用途 |
| --- | --- |
| `GET /api/bootstrap` | 页面标题、采集间隔、仓库配置摘要、待接入仓库和采集健康状态。 |
| `GET /api/snapshot` | 当前 `tasks`、`stories`、`sessions`、`logs`、`runtimes` 快照及生成时间；通过 `ETag` 支持未变化时返回 `304`。 |
| `GET /api/sessions/{session_id}/context` | 从本地 rollout 缓存读取一个会话的概览和有界记录页；不执行远程读取或命令。 |

未初始化快照会返回空状态。会话端点只接受单一路径段形式的 session ID；缺失会话返回 `404`，非法参数返回 `400`，同 ID 对应多个来源返回 `409`，本地缓存不可用返回 `503`。错误响应提供 `status` 和 `reason`，目前这些字段也属于内部草案。

### 会话概览字段

`status: "ok"` 时，响应主要包含：

| 字段 | 含义与边界 |
| --- | --- |
| `session.id`, `role`, `issue` | 会话标识、识别出的角色和关联 Issue；未关联 Issue 为 `null`。 |
| `session.source` | `kind`、运行时标签及来源文件名；不返回本机 rollout 缓存绝对路径。 |
| `session.issuedInstruction` | 从 rollout 头部解析的下发用户指令，必要时回退到已采集摘要。当前最多读头部 256 KiB；文本最多保留 65,536 个字符，超出时节选。`issuedInstructionTruncated` 标明被裁剪，或使用了回退摘要。 |
| `session.model`, `modelEvidence` | 优先采用整份会话采集到的末次模型及同次来源字段（例如 `session_meta.model` 或 `turn_context.model`），缺少时回退到头部可读取的模型及其来源；未记录时为 `null`。 |
| `session.workdir`, `workdirEvidence` | 经过路径规则筛选的工作目录标签及证据字段；未知或不符合安全标签规则时为空。 |
| `session.counts`, `entries`, `tokens`, `statsEvidence` | 采集器记录的计数、条目数和 token 统计，以及统计来源；不可用的对象/数字返回 `null`，不会拿 `0` 冒充未知值。 |
| `session.firstTs`, `lastTs` | 会话原始时间戳；未记录时为 `null`。 |
| `latestAssistant` | 最近可见的 Agent 输出，包含 `timestamp`、`text` 和 `truncated`；找不到时为 `null`。它只检查文件末尾最多 1 MiB，并把输出文本最多裁到 65,536 个字符。 |

文本裁剪常量按 Python 字符数工作，不是严格的 UTF-8 字节上限。UI 会在裁剪时显示节选提示。最近输出可能是过程消息；应结合任务回执和证据判断结果。

### 会话记录与分页

请求参数：

- `limit`：每页条数，默认 `50`，允许 `1` 到 `100`。
- `before`：非负字节偏移游标；使用上一页 `page.nextBefore` 读取更早记录。每一页从最近处向前扫描，页内按发生顺序显示。
- `type`：`all`、`message`、`tool`、`reasoning`、`event`、`meta`。当前实现收到未知类型时回退为 `all`。
- `q`：关键词，最多 200 个字符；超过上限返回 `400`。搜索匹配记录的文本、名称、角色和原始来源类型。

每个请求最多为当前页扫描文件末尾/游标之前的 **1 MiB** rollout 内容。为填充概览，同一请求还可能额外读取文件开头最多 **256 KiB** 来找指令和模型，并扫描文件末尾最多 **1 MiB** 来找最近可见输出。三段窗口可能相互重叠；`page.scannedBytes` 只表示当前页窗口，不包含概览的另外两项读取。单行 JSON 记录超过 **512 KiB** 时会跳过。

记录返回的 `type` 是 UI 用于筛选的规范类型；`source` 保留原始 rollout 记录种类，例如 `event_msg` 或 `response_item`。有些 rollout 会同时写入语义相近的两种镜像记录；它们会分别保留，由 `source` 区分，不会按文本去重。每条 `entries[].text` 最多返回 **16,384 个字符**的展示节选。搜索在整个当前窗口内的原始记录文本上匹配；如果命中内容位于返回节选之外，`matchBeyondPreview` 会提示命中在节选外。该提示不表示已搜索窗口以外的文件内容。

`response_item.reasoning` 只公开 rollout 中可见的 `summary`；`event_msg` 的 Reasoning 只公开 `summary_text`。加密或隐藏的 reasoning 内容不会返回。命令输入、工具输出和消息仍可能包含敏感内容，页面仅限制单条展示文本长度，不会对其做通用脱敏。

`page` 包含 `limit`、`nextBefore`、`hasOlder`、`scannedBytes`、`truncated` 和当前 `filter`。有界扫描意味着单页不保证覆盖整个长会话；需要较早记录时使用游标继续读取。类型或关键词搜索只针对当前页扫描窗口生效，不会触发一次无限制的全文件扫描。

## 验证方式

Python API 测试使用标准库 `unittest`：

```bash
python -m unittest discover -s tests -v
```

浏览器烟雾检查需 Node.js、本机安装 Playwright 和 Chrome，并要求快照里至少有一条任务和一条带时间戳的编码会话。先在一个终端启动服务，再运行检查脚本；脚本会把截图保存到 `build/_screenshots/`：

```bash
python app/run.py --port 8614
node tests/browser-smoke.cjs --url http://127.0.0.1:8614 --chrome "<Chrome 可执行文件路径>"
```

烟雾检查的命令和截图只说明检查过程及所采集画面；每次验收仍需核对截图、浏览器控制台和下列手工步骤。没有实际执行并记录的检查应保持“待验证”。

## 手工浏览器检查

在本地 Demo 和适合的测试会话上逐项检查，不要为了制造故障而停止或改动正在使用的 runtime：

1. 打开任务看板，确认四列、统计和任务详情；用标题、Issue、仓库和 Agent 角色搜索，检查“仅需关注”、零结果时“清除看板筛选”以及看板/紧凑列表切换。刷新页面后确认筛选与布局偏好保留；采集轮询时继续输入，确认搜索焦点和光标位置没有丢失。
2. 打开 `#/story/<id>` 和卡片详情，确认任务轮次、证据、PR 链接和 Agent 关联仍可查看；浏览器前进/后退时详情状态符合预期。
3. 在 Agent 页按角色筛选，搜索角色、会话 ID、Issue、指令或输出；切换最近优先/旧到新，确认顺序按会话时间变化。确认指令、最近可见输出、模型未记录状态和关联任务均使用实际会话数据。
4. 打开一个 Agent 上下文，核对源模型和证据来源、下发指令、最近可见输出、关联任务及来源文件名。等后台轮询一次，确认阅读中的内容、筛选、分页和滚动位置没有被自动替换；点击“重新读取”确认可请求较新内容。确认复制指令、复制 `#/agents/<session-id>` 深链接、直接打开深链接和 Markdown 摘要下载可用；下载内容只包含摘要，不应被当成完整会话。打开“完整记录”链接，确认旧 HTML 入口仍可达。
5. 在“会话记录”页切换类型并搜索关键词；核对原始 `source` 能区分语义相近的 `event_msg` 与 `response_item` 记录。用“读取更早记录”跨页，再返回最近记录；对超出 16,384 字符展示节选的命中，确认界面显示 `matchBeyondPreview` 提示。
6. 分别观察服务连接失败与运行时采集失败的状态文案，确认两者可区分且最后一次成功快照仍可读；有过期数据时确认过期状态会单独提示。此项优先用隔离的测试环境或已自然发生的状态验证，不通过干扰共享 runtime 制造故障。
7. 切换亮色和暗色主题；在桌面尺寸及约 390×844 的窄屏尺寸检查页面、抽屉、筛选和紧凑列表，不出现无法访问的控件或意外整页横向溢出。

检查记录应写明实际运行的 SHA、浏览器与视口、是否使用真实 runtime、执行结果，以及仍未验证的项目。不要用固定的任务或 Agent 数量替代行为检查。
