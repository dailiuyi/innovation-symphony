# 项目决策记录

记录日期：2026-09-28。来源：项目所有者在本次框架讨论中的明确陈述。已确认需求不代表已实现。与旧博客项目有关的运行状态及其其他会话决策不自动迁入本项目。

## IS-001：建立独立项目

- 已确认：“将目前的讨论结果抽离出来，形成一个新的 innovation-symphony 项目”。
- 范围：需求、决策、候选设计及已有后台原型形成独立本地仓库。
- 当前实现：目录 `E:\code\innovation-symphony` 是本轮本机放置选择，不是公司部署路径或技术栈决定。未创建远端、提交、部署或迁移旧控制器运行状态。

## IS-002：统一管理多仓库，仓库内独立执行

- 已确认：“开发一个 symphony 框架统一管理，多 repo 提供复用”；随后选择“各仓库独立处理任务”。
- 范围：统一管理仓库、配置与任务；第一版一个 Issue 仅修改其所在仓库，不做跨仓库任务协调。
- 适用业务：Unity、Android、iOS，Web 由用户负责。

## IS-003：长期目标部署到云端

- 最初用户选择专门开发机，不在个人本地电脑运行；随后明确“这套系统未来应该跑到云端上”。
- 当前决定：长期部署目标为云端，不依赖个人电脑持续在线。
- 替代关系：专用开发机不再是长期部署限制；首期落地环境与控制/执行节点分布未决定。本地原型预览不代表回退为个人电脑部署。

## IS-004：第一版支持 GitLab 与 GitHub

- 已确认：“GitLab 和 GitHub 都需要”。
- 具体实例、版本、账号、网络接入及认证方式仍待确认。

## IS-005：ready 驱动自动领取

- 已确认的最终要求：“机器人账号应该自动拉取这个已经打上 ready 标签的 issue 开始执行”。
- 当前决定：机器人发现 ready Issue 后自动领取并执行，不要求用户先指派机器人。
- 被替代：此前“指派给机器人即接手”的选择，以及讨论中的“先指派，再加 ready”建议，不再作为启动前置条件。
- 待定：初次接入存量 ready、重复扫描、中断恢复、移除/重新添加 ready 的行为；精确标签命名与状态维护规则。不得把这些技术策略当作已获批准。

## IS-006：评论解析模型，标签表达状态

- 已确认：“约定评论格式然后读取解析，标签只负责基本的 ready 和 review 还有 blocked 之类的”。
- 当前决定：用户在独立 Issue 评论中使用固定格式指令，由程序解析模型配置，不依赖模型理解普通评论。ready 同时是启动门槛，review/blocked 等用于状态表达。
- 示例命令 `/symphony models coder=... reviewer=...` 是建议语法，具体字段与冲突规则未定案。

## IS-007：仓库默认模型与用户覆盖

- 已确认：“需要保留选择 review 模型和编码模型的入口”；选择每仓库默认后又补充“如果检测到用户设定模型则使用用户选定的模型”。
- 当前决定：编码与 Review 分别有仓库默认值；用户对某角色显式指定时优先采用，未指定角色仍沿用默认。
- 边界：旧博客的固定 Reviewer、模型标签和提供商授权不作为本框架的产品默认。

## IS-008：查看型后台先做最简原型

- 当前交付：独立 HTML 原型，有演示数据、筛选与模型选择。持久化、解析、调用、计费和真实任务均未实现。
