## 本次范围

增加显式 `--preflight` 入口，在启动调度与领取之前校验配置并进行只读 GitHub 查询，输出明确的成功或失败结果后退出。正常服务启动路径保持兼容。查询使用现有 GitHub 客户端和错误处理，不另建调度器，也不自行确定后续升级策略。

## 验收标准

- PF-1：有效配置下，可从命令行运行 `--preflight`，输出可机器读取的 JSON 成功报告并以 0 退出；打包 escript 入口可用。文档给出操作示例，并区分体检成功与服务已接管。
- PF-2：校验 GitHub MVP 所需配置与有效查询状态；配置无效、MVP 未启用或无法形成有效查询时失败，且不发送远端请求。输出可识别原因并以非零退出。
- PF-3：通过只读 GET 查询任务单，正确处理分页；合法空队列也成功。HTTP、传输或响应格式失败必须报告失败，不能当作空队列通过；沿用现有客户端的有界请求策略。
- PF-4：体检不启动调度器或任务执行进程，不领取 Issue，不创建或改写任务回执、证据、工作区及运行配置，不发送评论、改标签或其他远端写入。失败路径也满足同一只读边界。
- PF-5：测试覆盖成功、空队列、分页、配置错误、查询失败和启动隔离；对命令行入口的结果及退出码有有效断言。保持标准格式、静态检查、全量测试及 100% 覆盖率门禁，不降低阈值或删除回归保障。
