## 一、目标与使用方式

让 coder 和 reviewer 独立选择已登记的模型服务配置，包括服务商、模型、有效参数、受控连接及凭据引用。本期落地 GPT 接入，为后续服务商扩展建立基础；DeepSeek 的接入实现和真实调用验收留到下一期。

平时使用项目对应角色的默认配置。创建 Issue 后，在独立评论中可分别为 coder 和 reviewer 选择完整预设配置；未指定角色使用项目默认。已有只指定模型名称的评论继续兼容。评论不含密钥、任意连接地址或启动命令。

未来可通过 View Config 页面修改项目默认配置；本期提供后台能力，不开发新设置页面。

## 二、当前问题与实现边界

现有 `Mvp.Config` 和 `Intake` 已支持两个角色的模型名称与独立评论解析，但执行仍复用全局 AppServer 启动配置。隔离路径共用一个认证来源，生成的推理参数固定为 `high`，尚无完整的角色服务配置解析、快照与持久管理能力。

调度、AppServer、编码、正式检查、Review、诊断、恢复和交付继续归 `elixir/`。复用现有实现，不新增独立调度器。View 维持独立采集和只读展示，本期配置后台不能令其直接改写任务回执或控制执行。

## 三、本次开发范围

### 1. 按角色配置模型服务

每个角色可独立设置服务商、模型名称、受支持的推理参数、受控连接配置及凭据引用。允许同一服务商的不同模型，也为后续不同服务商接入保留扩展能力。

本期 GPT 调用必须实际使用对应角色的配置。修改 reviewer 配置不能影响 coder；不同调用之间不通过改写共享全局配置切换账号、连接或参数。并发隔离测试用于验证该性质，不作为新增并行调度或多仓库功能的要求。

### 2. 保留并扩展独立 Issue 评论

实现前确认现有评论入口、字段、作者权限、确定性解析及累计规则，补充兼容回归。评论允许分别选择系统已登记且获准的完整预设配置，以及表达使用项目默认；具体新增命令语法待设计。

配置优先级：Issue 显式指定的角色配置、项目对应角色默认、仅用于兼容迁移的旧版默认。授权评论中的无效显式选择必须报错，不能静默回退。旧模型评论与新配置评论的组合、冲突及恢复默认语义须明确说明并测试，不能由模型猜测自由文本。

同名模型可以对应不同已登记配置。评论只选择受控标识，不指定任意服务地址、凭据、启动命令或执行权限。

### 3. GPT 模型目录和能力校验

模型目录支持更新和刷新，覆盖接入渠道中全部符合条件的 GPT 型号，不在业务代码中固定为单个型号，也不以任意 `gpt-*` 字符串放行。可用型号须满足当前账号权限、服务商及协议支持、对应角色所需工具和输出能力，并遵守管理员限制。

目录中区分已发现、待验证、可用于对应角色、被禁用或不兼容等状态；目录发现与真实推理验证不能混为一谈。能力证据须绑定对应服务配置与角色，不能用某个账号或角色的验证结果证明所有配置可用。不能取得完整目录时提供人工登记与验证方式，并明确获取失败及旧目录时效。

不支持的模型及参数在调用前给出明确原因。新 GPT 型号通过账号权限、协议、对应角色能力及管理员限制校验后自动成为相应角色的可选项，不再逐型号等待人工启用；不自动改变角色默认值。不支持的推理参数不能原样发送。具体校验方式和证据来源待设计，目录发现或校验未完成不能直接标为可用。

### 4. 领取时固定完整执行配置

解析并持久保存两个角色的最终服务配置及来源，包括受控配置标识与版本、服务商、模型、有效参数、连接与执行适配身份、凭据引用。快照不保存秘密值。

默认修改只影响新领取任务；已领取任务的编码、Review、重试、诊断及恢复沿用原配置，领取后的普通模型评论变化不能悄悄改写当前任务。需要新一轮执行时须明确记录，并遵守原恢复审计和预算规则。

审查建议：现有诊断沿用 coder 模型，本次延续为继承被冻结的 coder 服务配置，同时保留只读及诊断结构要求；不新增第三个模型选择入口。

必须覆盖所有恢复入口。现有 `mix mvp.external` 会重新解析当前模型并与旧模型比较，不能仅在新任务路径增加快照而留下该行为与需求冲突。凭据失效或权限撤销应停止相关调用；冻结配置不绕过当前权限校验，也不静默换用另一套配置。

旧配置和旧回执迁移不得用变化后的默认值重新解释历史任务；缺少的连接或验证证据如实报告，不补造历史。

### 5. 默认配置后台基础

提供统一读取、校验、保存及持久化能力，明确配置文件与运行时设置优先级，以及即时生效和重启生效的边界。配置保存前校验，失败保留旧值；并发保存不得静默覆盖，重启后配置仍有效。

读取不返回密钥，只显示安全引用及凭据是否配置。具体本地管理入口待设计；本期不强制新增网络写接口。如果暴露网络写接口，必须同时完成身份与权限检查，不能留下未保护的修改接口。

## 四、失败处理与可追溯性

模型不存在、账号无权限、协议或角色能力不支持、凭据缺失或失效、超时、限流、余额不足，以及 Review 结构错误，都须给出明确原因并按现有有界恢复规则处理。不能静默换服务商或模型，不能将调用失败计为审查通过。

记录配置来源、请求的服务商和模型，以及服务端可确认的实际模型信息；不能确认实际型号时标为未知。用量缺失同样为未知，不能记录为零。日志、任务快照、接口和报告不得包含密钥。

## 五、安全与兼容

旧配置和旧评论方式兼容，提供迁移及回滚说明。reviewer 的只读权限、执行隔离、正式检查和最终候选 SHA 绑定保持有效；候选变化后旧批准不能复用。服务商扩展不能放宽工具或隔离权限。

本期 GPT 接入的真实验证与代码提交、远端发布、运行安装、真实 Issue 派发分别记录和授权；本文不自动授予这些操作，也不授予向 DeepSeek 发送代码或审查材料的权限。
