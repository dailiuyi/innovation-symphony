# Issue #5 · 运行器看门狗：进程死亡自动拉起（编号以发布时为准）

草稿状态：2026-09-29 根据用户逐项选择及随后批准的更新计划修订，行为边界见 IS-030；同日按用户授权吸收评审意见，补齐凭据验收前置、进程身份及维护操作合同。具体工程参数与部署方式不作为用户已批准的产品决定。本轮确认替代初稿中的严格父子关系限制、维护锁无人工写入方及含糊的预算恢复表述；文档更新不代表功能已实现、Issue 已发布或运行服务已安装。

看门狗是"系统能养活自己"的第一步，一切自动迭代都以运行器在线为前提。本 Issue 假定 WSL／Linux 宿主持久在线，只做运行器进程退出后的活性保障，不做版本更新；自动更新、装后体检与自动回退属 [升级接棒草稿](002-graceful-upgrade-handover.md) 及 IS-028 后续范围。

## 本次范围

增加一个独立于运行进程的守护进程：周期检测确认属于本服务的运行器进程是否存在。未暂停时，正常退出与异常退出均触发恢复；仅在指针有效、无现存运行器、预算可用且退避到期时，以"版本指针"指向的固定安装拉起。不检测卡死、本地心跳或业务异常，不主动终止仍然存在的运行器。

版本指针是看门狗选择固定安装的依据；看门狗只读指针，不切换版本，也不执行更新或回退决策。已有运行器时，指针变化本身不触发停止或另启进程。本次交付指针的格式定义与读取端，自动更新写入端不在本次范围；维护锁与重启状态信号作为后续更新流程的另外两个衔接点。

本次同时提供人工暂停、解除维护暂停及同版本耗尽后的明确恢复操作。暂停只禁止自动拉起，人工停机按"先暂停值守，再停止运行器"执行；不新增自动停机或任务处置逻辑。

## 设计约束

- 故障隔离以行为验收：看门狗崩溃、被强制结束或重启，不得终止正在运行的服务或造成重复启动；不再强制指定两者的父子关系。
- 防双启动：确认属于本服务的运行器进程仍存在时，人工与看门狗入口均不得另启；存在维护锁时，看门狗不得自动拉起。人工显式启动仍须遵守同一进程身份核对与防双启动约束，且不会解除维护暂停或重置自动启动预算；不将进程存在等同于业务健康。
- 进程身份合同：裸 PID 或端口可访问均不能单独证明归属。记录并核对宿主启动标识、PID 与进程启动时间（或等价的不可混淆进程身份），同时匹配本服务的固定运行配置路径、启动命令及记录的实际安装路径。指针已改变而旧版本仍存活时，仍须识别并阻止另启，不能只匹配当前指针版本。状态端口仅作辅助冲突检查，端口未响应不能被解释为进程死亡；身份无法核实、信息冲突或存在无法归属的端口占用时，保留证据并阻止启动，不终止未知进程。
- 启动互斥：人工入口与看门狗在同一服务级启动互斥内复核进程身份，看门狗自动入口额外复核维护状态；互斥覆盖从检查到启动、身份记录落盘的过程，两个检查同时看到“无进程”也不能产生双启动。
- 维护暂停持久化：支持人工设置与解除维护锁，只有明确解除才恢复；终端退出、看门狗重启或经过一段时间均不自动解除。本次不实现自动更新器的写锁逻辑。解除维护暂停不清除已耗尽的版本预算。
- 统一启动预算：每次实际启动尝试均计入本轮预算；启动失败与启动后快速退出统一按配置退避，达到上限后停止自动启动并标记该版本待人工，不在同一故障上无限打转（纪律同 IS-026"达到上限保存终态与证据，不自动扩大预算"）。指针非法、维护暂停等未发生启动尝试的情况只记录阻塞原因，不消耗启动预算。
- 稳定运行与历史分离：尚未耗尽预算时，进程连续存在达到配置时长后清零本轮计数；这里的稳定仅指进程持续存在，不代表业务健康。历史启动、退出、失败与恢复证据始终保留，不采用滑动时间窗口自动解除待人工状态。
- 预算按固定版本保留：同版本耗尽后，修复环境等操作须配合明确的人工恢复，才能获得新一轮机会；外部操作者（当前为人工，未来可为另行实现的更新器）将指针切到其他未耗尽预算的固定版本后，看门狗才可按该版本预算自动尝试，且仍须满足其他启动条件。看门狗不选择替代版本、不写指针；曾耗尽的版本切走再切回不能重置预算。人工恢复保留此前终态与证据；维护暂停仍须单独解除。
- 看门狗重启不重置维护暂停、本轮计数、退避或待人工状态。重启后重新核对现存进程，不以自身重启为再次启动运行器的理由。
- 暴露状态文件，区分本轮启动尝试计数与历史重启记录，包含当前指针版本、观察到的运行版本与进程信息、维护暂停／退避／待人工状态及最近动作。供后续装后回退判断"刚切换版本反复崩溃"使用；本次只暴露，不实现回退决策。

## 验收标准

- WD-1：运行器正常或异常退出后，看门狗在配置的检测周期内发现退出；实际拉起须等待指针有效、未暂停、预算可用及退避到期，不将检测时限等同于无条件启动时限。以指针指向的固定安装启动，沿用经核实的环境、工具链、工作区和任务状态，不重建或清空。无人值守凭据来源是本项通过的硬前置：验收记录必须注明预配置的环境变量或受限权限文件等实际来源、访问权限及注入路径（不记录秘密值），在运行器退出后无操作员输入、确认或登录的情况下完成自动拉起；启动所需其他认证也须预配置。缺少该前置或恢复时人工补输 token，WD-1 均不得判通过。凭据缺失或不可读取时，不执行启动，输出脱敏原因并保留证据，不交互等待输入。
- WD-2：指针缺失、非法或指向不存在的安装时，不启动任何进程，输出可识别原因并留证据；不猜测版本、不回退到任意旧安装。
- WD-3：按进程身份合同确认本服务运行器仍存在时，任何入口均不重复拉起；存在维护锁时，看门狗不自动拉起。并发启动仍保证同一时刻至多一个运行器进程。覆盖 PID 被无关进程复用、身份记录缺失／不匹配、端口被无关服务占用、运行器存活但端口无响应，以及指针改变但旧运行器仍存活的情况；不得误认归属、误杀进程或据端口无响应另启。人工暂停不终止现有进程，暂停跨终端退出、人工显式启动及看门狗重启保留；明确解除后恢复值守，但不能绕过退避或清除耗尽预算。
- WD-4：启动失败与启动后快速退出统一计入本轮启动尝试预算并退避；达到上限后保留完整证据、停止该版本的自动启动并进入待人工状态。未耗尽时，持续存活达到配置时长清零本轮计数，但历史记录不删除。耗尽后同版本必须明确人工恢复，等待或重启看门狗不能解除；其他版本使用各自预算，切回已耗尽版本仍阻塞。
- WD-5：每次检测、拉起、阻塞、放弃及人工暂停／解除／恢复均留本地证据（时间、原因、指针版本、观察到的运行版本、进程信息），可审计。看门狗不改任务回执与既有证据目录，不执行远端写入（评论、标签、PR 均不做）；运行器启动后的既有任务执行合同不变。
- WD-6：在途任务安全完全依赖既有 at-most-once 领取与中断恢复规则；本次不新增任务处置逻辑，不为中断场景设置新的产品默认值。
- WD-7：状态文件在正常、拉起、维护暂停、阻塞、退避、待人工与人工恢复后内容正确，本轮计数与历史记录不混淆。测试对主循环、WD-3 各身份异常与并发防双启动、正常／异常退出、启动失败、退避与上限、稳定清零、跨版本预算、人工恢复及指针异常路径均有断言；覆盖无人值守凭据注入、凭据缺失／不可读取及日志脱敏、暂停持久化、看门狗重启后状态保留，以及看门狗崩溃／被强制结束／重启不影响现存运行器且不重复启动。保持标准格式、静态检查、全量测试及 100% 覆盖率门禁，不降低阈值或删除回归保障。

## 工程默认与待定

检测周期、退避节奏、启动尝试上限、稳定存活时长及指针／维护锁／状态文件路径均为可配置工程参数，不登记为用户指定的产品决定。状态文件的具体字段格式及人工操作命令属于工程设计，须符合上述行为合同。

无人值守凭据来源作为 WD-1 的强制验收前置，不再仅以“实现前核实”搁置；本次实现须接通所选非交互来源，并在 OPERATIONS 说明预配置、权限及验证方法。来源可采用部署环境注入的环境变量或受限权限文件，具体选择为工程安排；不包含凭据自动签发、刷新或集中密钥管理。预配置可由人工一次完成，但后续故障恢复不得要求操作员再从 gh 活跃账号取 token 经标准输入喂给启动器，也不能依赖已退出运行器的环境。启动器内部以管道传递预配置凭据不受此限制；凭据不写入指针、状态或证据。

实现前另须核实固定安装路径、工具链环境与防双启动入口，不直接复用未经核实的历史启动器。历史安装验收的队列预检须与既有 ready 领取合同核对，不将一次性安装限制误作产品规则。交付须补全 [OPERATIONS 的看门狗维护流程](../OPERATIONS.md#看门狗维护流程)，给出实际实现的暂停、状态核验、解除暂停与预算恢复命令，不能以未实现的命令示例代替交付。

看门狗自身以何种机制常驻及退出后如何恢复（Linux／WSL systemd、启动脚本或等效物）属部署安排，本次只给推荐并记录于 [OPERATIONS](../OPERATIONS.md)，不在代码内固化，不纳入安装或看门狗自身自动恢复的实测交付。上述故障隔离与状态恢复测试仍属于代码验收。本次只落本地证据，远端通知渠道留待后续讨论。

## 执行与交付

沿用 Astra high 编码与独立 Review，自动恢复策略按当前运行配置生效。每轮保留完整检查日志与候选证据，交付终点为 Draft PR，由人决定合并与安装；标签由人维护。看门狗代码随常规门禁交付，本任务不修改运行版本。

2026-09-30 的 IS-040 更新交付时机：完整正式检查通过、独立 Review 确认没有代码缺陷且仅剩 WD-1 等真实外部验收条件时，允许先交付明确待验收的 Draft PR，任务仍保持 `awaiting_external`。PR 写明未完成项、候选 SHA、所需证据与接手责任，不自动关闭 Issue 或声称 WD-1 已通过；外部证据核验后仍重新完整检查和 Review，再更新已有 PR。完整合同见 [EXTERNAL_HANDOFF.md](../EXTERNAL_HANDOFF.md)；此路径由 IS-041 授权实现、安装和继续原 GH-5；预算仅通过统一审计入口追加有限活动窗口，原冻结验收标准保持不变。

## 后续范围

自动更新、装后体检与自动回退、优雅停机、完整 A/B 升级互斥、通知渠道扩展、云端部署，以及宿主故障恢复和开机自启均为后续范围。进程卡死或业务异常的健康检测与自动终止不在本次范围。本 Issue 的防双启动约束仍必须满足，并为后续提供三个钩子：指针读取端、维护锁语义、重启状态信号；不预先实现其决策逻辑。
