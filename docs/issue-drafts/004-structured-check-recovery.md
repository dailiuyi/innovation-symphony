## 已批准实施范围

### 1. 让测试框架提供可核对的结果

由固定检查 runner 加载候选工作区之外的 ExUnit formatter，保留正常控制台输出，并额外记录每项失败的异常类型、测试计数及套件完成事件。分类依据为真实进程退出码和结构化报告，测试阶段不再依赖某句英文断言消息。

- 完整测试报告中的普通或自定义 `ExUnit.AssertionError` 返回可返工结果 10；已识别的覆盖率不足、格式及编译失败沿用明确分类。
- 未识别异常、环境故障、超时、进程被杀，以及报告缺失、截断、重复完成或与退出码矛盾均停止。混合失败必须逐项解释，不能因为其中一个断言就判整套可修复。
- 成功也校验报告完整性；零测试或缺失完成标记不能仅凭 exit 0 通过。
- 每次检查创建独立目录及运行 ID，绑定候选、检查阶段和 runner/formatter 摘要；拒绝旧报告和错误身份。保留完整 stdout/stderr、结果文件和分类原因。
- 这些绑定用于防止旧结果误用及意外覆盖；同一测试 VM 不是恶意代码隔离边界，不将其描述为新增安全沙盒。

当前 Elixir 1.19.5 的隔离小样例已确认：自定义断言与 `RuntimeError` 可分别读出真实异常类型及完整结束事件。真实 Mix、覆盖率和异常中断组合仍须在实施时验证。

### 2. 统一操作者复检入口，保留执行历史

使用一个小型操作记录组件管理内部 `recheck`，复用现有检查、编码和 Review 流程，不另建调度器。

- 仅接受明确选定的 blocked 回执，核对原始回执摘要、仓库/Issue、候选、base、模型、分支、工作区、轮次及预算。
- 每次操作有唯一 ID 和独占证据目录；同一执行还必须共用一把互斥锁，防止两个不同操作 ID 并发。
- 保存输入回执、授权上下文、运行版本、命令、前序操作及最终回执摘要。正常完成先写终态再释放新互斥锁；中断保留占用，禁止自动接管。
- 旧 guard 和记录原样保留。确认旧监督进程已结束、已有结果文件与当前回执一致后，追加旧操作结束核对记录，再明确建立新操作与旧记录的关联。
- 相同候选重新检查不消耗返工；进入新的编码轮才从 4/5 增为 5/5。不得清空历史、恢复旧回执或增加预算。

### 3. 让编码 Agent 修复 #3 的真实缺陷

复检确认失败可返工后，将完整日志和 `94e3768` 中已验证的最小路径修复作为明确诊断材料交给编码 Agent。由 Agent 在原候选上实现兼容修复，并保留真实打包入口测试；操作者不直接替它修改候选代码。

保持原始 base 与冻结回归不变，不整体合入最新 main 来绕过旧基线。新的 `check_baseline.py` 必须显式接收原 baseline 路径，从原快照组装检查目录，使用外部新 formatter；不能按新 runner 的安装目录偷偷换成新基线。

修复后重新执行完整候选检查、原冻结回归与独立 Review。通过后交付 Draft PR；最后一次仍失败则保留完整原因并停止。

## 验收要求

| 场景 | 预期结果 |
| --- | --- |
| 当前同类自定义断言，完整报告，Mix exit 2 | 自动归为可返工 10 |
| 普通断言与未知异常混合、真实权限或超时故障 | 停止，不进入编码重试 |
| 缺报告、旧运行 ID、错误 SHA、计数矛盾、重复完成、formatter 被移除 | 停止，不回退到猜测文本 |
| exit 0 配失败报告，或实际零测试 | 不通过 |
| 套件完整、仅覆盖率不足 | 可返工，门槛仍是 100% |
| 全部检查通过且覆盖率 100% | 进入独立 Review |
| 两个复检操作并发、同一操作重入、回执回滚 | 拒绝重复执行 |
| 复检中断 | 保留锁和证据，不自动重启 |
| 原候选复检通过 | 不调用 coder、不消耗返工 |
| 当前候选需编码修复 | 仅使用剩余一次，计数连续到 5/5 |
| 最后一轮再次检查或 Review 失败 | blocked，不自动增额 |
| #3 恢复前后 | 原 base、模型、历史日志及旧 guard 保留 |

控制器改动须通过 Python 回归、真实 ExUnit/Mix 集成检查、Elixir 全量门禁和独立审查。#3 则以真实打包成功 JSON/退出码、异常响应失败、只读边界、原冻结回归及 Review 为准，不能用覆盖率数字代替行为验收。
