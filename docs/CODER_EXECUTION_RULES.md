# Coder 自主测试与隔离执行规则

状态：IS-033 的本地实现、完整验证及控制器安装已完成，堵塞的 #5 已恢复至隔离 coder 自检；本轮 Review 尚未完成。具体版本、证据及暂时暂停自动领取的运行安排见 [验收记录](VALIDATION_CODER_ISOLATION.md)。来源：IS-031 的同会话自检方向、IS-032 的规则授权及 IS-033 的实施授权。

四条底线及环境内充分放权是已确认原则。下文的执行流程、控制措施和验收用例是助手依授权制定的设计，不能表述为用户逐项指定的实现。当前本地实现选择见第 6 节，不指定永久云架构。

## 1. 总体规则

coder 在单个任务的隔离环境中，自主完成修改、测试、诊断和修复，不逐条审批命令，也不维护 shell 命令黑名单。权限约束由环境和控制器执行，不能只依赖提示词。

流程为：准备并验证环境 → 同一次 coder 会话内自检与修复 → 提交候选供控制器验收 → 控制器完整检查 → 新鲜独立 Review → Draft PR。Git 提交和发布仍由控制器负责，人工合并与安装边界不变。

自检是编码阶段的内部活动；一次测试失败不自动结束 coder 会话，不直接消耗一次外层返工。内部活动的时间、模型用量和资源消耗仍计入总预算。正式检查或 Review 失败后的返工沿用恢复合同；是否复用原 coder 会话另外设计。

## 2. 环境内允许的行为

在冻结的任务范围和资源预算内，coder 可以：

- 执行任意语言的测试、静态分析、编译、格式化和诊断命令；编写临时脚本。
- 按文件、用例、标签或失败项选择测试，临时排除无关项，重复验证修复。
- 在任务内部启动子进程、本地 HTTP 服务、模拟数据库及其他临时依赖，使用环境内部端口。
- 修改任务源码和测试，整理任务自己的临时文件、构建产物和私有缓存。
- 在任务环境内通过获准的依赖获取通道安装开发依赖；不能修改宿主工具链。依赖安装脚本与测试代码受到相同隔离限制。
- 查看完整自检输出和控制器提供的只读反馈。临时诊断结果不能冒充正式验收结果。

自由选测不等于可以把持久化的跳过标记藏进候选。源码、测试及配置的最终变化都进入 diff 和 Review。

## 3. 四条强制底线

### B1：不能影响宿主、其他任务和运行服务

- coder 和它启动的所有进程，只能写本任务源码副本、临时存储及私有构建缓存。控制器安装、状态、凭据、正式证据、原始仓库及其他任务不可写；敏感资源不暴露给任务读取。
- 不暴露宿主管理接口、容器控制 socket、宿主进程空间或特权设备。环境内启动服务只在任务网络可达，不自动发布到宿主或公网；不能通过宿主网关接触运行服务。
- 受保护 Git 元数据仍由控制器维护；必要的读取通过只读接口或视图提供。路径和产物导出须防止符号链接或路径穿越越界，不依赖路径字符串前缀判断。
- 共享工具链或缓存只能以不能污染其他任务的方式提供；任务可写缓存不直接成为其他任务可信输入。
- coder 结束、超时或提交验收前，必须确认其后台子进程已停止。不能让残留进程修改待验收候选。
- 正式检查也执行候选代码，因此必须具有同等隔离边界。控制器拥有检查调度权，不表示测试应继承控制器账号的宿主权限。

### B2：不能擅自操作真实外部系统

- 测试命令不能取得平台推送、生产数据库、云管理或部署凭据，也不能读取宿主 HOME、SSH agent 或模型账号凭据文件。只删少数环境变量不算完成凭据隔离。
- 模型连接使用受控的代理或凭据边界，与任意测试子进程隔开；不能为了调用模型，把宿主完整账号环境传给测试。
- 环境内部通信允许；外部网络按任务冻结的网络策略执行。依赖获取与真实业务 API 操作分开，不把“能下载依赖”解释为无限制外网访问。
- 实现时选定依赖代理、预置缓存或受限出口方案，处理重定向及宿主／内网地址访问；不得只凭 GET 方法或域名名单宣称绝无数据外发风险。
- 普通自检和正式回归使用本地模拟服务及测试数据。真实平台测试须有单独授权的目标、凭据和预算，不能由 coder 设置开关后自动获得权限。
- Git 推送、Issue 评论和 PR 创建继续由已有授权范围内的控制器交付阶段执行；本规则不增加远端写入权限。

### B3：不能自行降低最终验收标准

- 正式检查入口、执行范围、覆盖率门槛、冻结基线和结果判定策略在任务开始前由控制器确定，保存版本或摘要，coder 不能修改其有效值。
- 候选可以包含检查脚本或配置的代码修改，但这些修改不能自行替换本轮可信检查入口或降低本轮门槛。任务本身要求修改门禁时，也须在执行前明确对应验收合同，不能由候选自我批准。
- 固定入口不能仅调用候选可任意重定义的命令就认定门禁受保护；实现须验证实际生效的检查项、阈值及报告与冻结策略一致。
- 控制器对停止写入后的候选生成固定快照／提交，在独立验证环境运行完整候选检查及冻结基线回归；正式检查不得复用 coder 可篡改的通过记录或未验证构建产物。
- 正式结果绑定候选、检查策略和执行身份；缺失报告、零执行、退出码矛盾、证据被改写或检查后源码变化均不得通过。
- 独立 Reviewer 接收完整 diff、检查结果及测试变化，检查删减断言、移除测试、新增跳过、扩大过滤或覆盖率排除等是否削弱验收。静态规则可提示变化，不能宣称自动识别全部语义弱化。

#### 测试跳过与排除

不要求维护逐个测试的固定允许跳过清单。自检可自由选测；正式检查由冻结的执行配置决定范围。

正式报告必须区分通过、失败、跳过、排除和未执行，保留身份及可获得的原因。与冻结基线相比，报告测试清单和相关配置的变化；新增测试、重命名及合理删除不能仅按数量一律判错。

沿用已有真实平台测试的显式启用条件；未启用时标明“未验证真实平台流程”，不计作通过。新增跳过、删除断言等变更进入独立 Review：有任务依据且保留等效验证的调整可以接受；规避失败或无依据削弱要求必须返工。若正式必测项因环境问题没有执行，应修复环境或明确阻塞，不能以 skip 代替通过。

100% 覆盖率仍是冻结统计范围内的门槛，不表示所有模块、全部分支组合或真实平台流程均已验证。

### B4：不能无限消耗资源

- 任务启动前必须明确总时限、CPU、内存、磁盘、进程数量及模型调用预算。参数由实现和运行环境确定，不在本设计中虚构用户指定数值。
- 资源限制在环境外强制执行，涵盖子进程、后台服务、安装脚本和正式检查。限制并发与磁盘占用，不能仅靠模型承诺自觉停止。
- 同一会话内的多次模型 turn、重试和自检都计入总用量；保留单次命令时间和结果。不能把“一次会话”当成“一次模型调用”隐藏消耗。
- 单条命令达到额度时终止该命令及其后代，保留失败结果；环境健康且总预算尚余时，coder 可选择更小的检查或改正命令继续。任务总预算耗尽则停止整个任务，不自动增额。
- 总时间、调用计数及用量不因外层返工、环境重建或经授权续跑而归零。费用未知时如实标未知，不能伪称已提供精确金额熔断。
- 证据存储由控制器管理并预留容量。输出超限要明确标识，不能把截断的正式报告当完整结果；必要证据无法保存时停止，不能静默丢弃后继续交付。

## 4. 提交条件与失败处理

环境准备阶段先验证工具链、依赖、任务写入范围、本地端口及子进程能力。准备失败由控制器处理环境问题，不让 coder 在无测试能力的环境中盲目循环。

coder 自检通过后提出提交验收：提交代码变化、已执行命令与结果、未执行项及原因。控制器要求最后一次完整自检对应当前源码；自检已知失败则继续留在编码阶段，不能靠文字宣称完成。无法运行必测项时进入环境诊断，不悄悄省略检查。

提交时停止任务写入和残留进程，建立不可变候选，再在同版本工具链及等效依赖条件下正式检查。自检结果仅帮助决定何时提交，不授予正式通过。缓存、源码或依赖更新后必须重新取得适用证据。

| 事件 | 处理规则 |
| --- | --- |
| 自检发现格式、类型或断言错误 | 在同一 coder 会话内修复、复测，预算持续累计 |
| 临时命令选择了无权限资源 | 返回具体拒绝原因，允许 coder 在原边界内换方法；不自动提权，也不因一次拒绝立即要求人介入 |
| 测试需要未提供的环境能力 | 自动诊断，在既有授权内修复环境；不能扩大外部权限或降低门禁 |
| 隔离措施失效、受保护资源被改写 | 停止任务并保留证据，不按普通代码返工继续 |
| 正式检查或有效 Review 拒绝 | 沿用自动恢复分类、冻结范围和预算；新候选重新完整检查及独立 Review |
| 疑似偶发测试失败 | 保存首次失败及复测证据，不能只保留一次成功便判通过；有限复检策略尚待实现设计 |
| 总资源预算耗尽 | 停止并保留当前候选和原因，不重建环境绕过预算 |
| 需要新增权限或需求决定 | 说明具体缺口及已有证据，再交人工决定 |

以上状态描述是行为合同；新增配置和审计续跑入口见第 6 节。

## 5. 验收规则

使用临时验收环境、伪凭据和受控目标验证边界，不对真实服务做破坏性探测。

| 编号 | 必须证明的行为 |
| --- | --- |
| C-01 | 同一次 coder 会话中完成一次真实测试失败、修改及复测成功，再交控制器；中途不重开外层返工 |
| C-02 | 格式、lint、类型分析、测试和覆盖率可以实际执行；本地服务及子进程正常工作，不再被 Mix.PubSub socket 限制阻断 |
| B1-01 | 尝试读取伪敏感文件、写任务外目录、通过链接越界、操作模拟宿主进程或管理 socket 均被边界阻止，正常任务内操作仍可用 |
| B1-02 | 后台进程在验收交接和超时后不能继续修改候选；正式检查里的同类越界操作同样失败 |
| B2-01 | 依赖获取按策略可用；直接或经重定向访问不允许的外部目标、宿主服务及伪凭据均被阻止；实际业务平台零写入 |
| B3-01 | 修改候选检查脚本、阈值或测试过滤不能悄悄改变本轮正式门禁；伪造通过文件无效 |
| B3-02 | 局部自检成功但完整回归失败时不得交付；skip／exclude 如实报告，测试弱化变化进入独立 Review |
| B3-03 | 日志缺失、报告截断、零执行、结果矛盾或候选变更不得通过；已有可选真实平台测试的跳过不冒充通过 |
| B4-01 | 有界模拟 CPU、内存、磁盘、进程及时间超限，验证任务可终止、宿主和其他任务保留资源；不用真实无限消耗来测试 |
| B4-02 | 同会话多 turn、外层返工及授权恢复后的计数不归零，首次失败和未知费用均保留 |
| C-03 | 环境准备失败不会交给 coder 反复猜测；需要新增权限时不会自动扩大边界 |

效率验收同时记录从开始编码到进入 Reviewer 的总耗时、模型用量、正式检查首次通过率和外层返工次数。使用相同任务与工具链条件比较，不能只把多轮隐藏进一次会话便声称提速，也不预设未经测量的提速百分比。

## 6. 实施接缝与当前限制

继续复用 `elixir/` 的调度和 AppServer，在现有工作区准备、编码阶段、检查阶段和回执用量记录处接入。Python 保持检查／验收脚本用途，不新增独立后端调度器。

未开启隔离的兼容路径仍保留，不能把 `workspace-write`、目录分离或哈希绑定当作本规则全部要求的证明。新配置必须显式启用；启用后准备失败即报错，不静默回到宿主执行。

本地后端使用 Linux bubblewrap：任务文件副本为 `/workspace`，Git 元数据只读；工具链、依赖、原始基线和控制器证据分别只读提供。任务 PID、网络和挂载空间分离，外网关闭，内部 loopback 可用。私有存储、cgroup CPU／内存／进程限制和外部墙钟超时覆盖整个进程树。任务结束须先清理后代、导出产物并写完成证明，控制器才导入普通源文件；链接和特殊文件拒绝导入。

宿主 Codex AppServer 使用独立的受控 HOME，只保留模型认证，禁用宿主插件、hooks 和代码扩展。通过 `environments.toml` 的 stdio executor 将模型的文件和命令操作转发到任务环境，`include_local=false`，启动时验证没有 local 回退。测试进程不获得模型认证或 GitHub token。

当前依赖采取预置离线方式；不提供任意下载或新增真实平台访问。Mix 与静态分析缓存写入任务私有 HOME，不能复用其他任务污染的 PLT。OTP 所需的原安装前缀只读映射到同一份受信工具链，不挂载其父目录。正式检查在新实例里构造临时项目，使用冻结基线的 Mix 配置、lockfile、formatter、Credo、WORKFLOW 与 runtime config，分别运行格式、specs、Credo、覆盖率、Dialyzer、构建及基线测试；不会调用候选改写的顶层检查脚本。报告保留逐测试状态和跳过原因。测试代码本身仍须独立审查，这不是抵御任意恶意仓库的报告防伪平台。

`mvp.sandbox` 配置示例（路径与数值均为工程安排）：

```yaml
sandbox:
  enabled: true
  root: /var/tmp/innovation-symphony/sandboxes
  toolchain: /var/tmp/innovation-symphony-toolchain
  codex: /absolute/path/to/native/codex
  dependencies: /absolute/fixed-release/elixir/deps
  trusted_root: /absolute/fixed-release
  auth_home: /absolute/host-only/codex-home
  memory_mb: 4096
  disk_mb: 8192
  pids: 256
  cpus: 4
```

沙箱总时限取本阶段及任务剩余额度。控制器原模型调用次数、总时间和用量记录继续有效。`Executor.resume_recovery/3` 只用于有明确授权的已冻结任务：绑定原始 receipt 与工作区摘要，校验冻结 base、模型、Git 元数据和基线，审计执行策略变化及有限的追加墙钟额度；历史次数与开始时间不变。中断 coder 的未提交工作保留，再交 coder 继续修复；有效 Review 拒绝不会被同候选重复 Review 绕过。

当前同会话自检通过明确的 Agent 指令组织；尚未实现“最后自检与最终源码”的机器签章。控制器实际强制的是停止任务后对新候选重新执行独立完整门禁，因此不能把模型的自述当作通过证明，也不能仅凭接入完成宣称外层返工已减少。

已授权本次本地实施和 #5 恢复，未授权自动合并或安装 #5 候选、其他新任务派发或生产／云部署。实际验收结果和剩余限制须随操作记录更新，不能仅凭配置或 mock 测试宣称四条底线全部验证。
