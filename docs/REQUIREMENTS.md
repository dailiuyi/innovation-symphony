## 产品与部署

项目原型与设计参考基线为 [OpenAI Symphony](https://github.com/openai/symphony)（本轮补充，见 IS-010）。已确认直接基于官方源码修改（IS-014），复用其 Elixir 实现；旧博客实现仅作经验参考。

项目名称为 `innovation-symphony`，提供统一管理、可供多个 repo 复用的 Symphony 框架。主要面向 Unity、Android、iOS，兼顾用户负责的 Web 项目。

长期目标部署到云端，不依赖个人电脑持续运行。首期环境、云提供商、执行节点位置和操作系统尚未决定；不预设所有平台可以在同一种云主机上完成构建。

## 平台与任务范围

平台分期已更新（IS-012）：MVP 先实现 GitHub，随后由 Symphony 迭代自身；GitLab 后置，双平台仍为后续目标，不再要求 MVP 同时支持。一个 Issue 对应所属仓库内的任务，仓库之间独立执行，不包含跨仓库修改或任务编排。

## 任务入口

用户在代码平台的 Issue 中描述需求，可先发一条独立评论指定模型，然后添加 ready 标签。机器人自动发现带 ready 标签的 Issue，领取并开始执行；不要求用户预先将 Issue 指派给机器人。

ready 表示可开始执行，review、blocked 等标签表达基本工作流状态。模型配置不放在标签中。标签是否带命名空间、完整状态集合以及谁维护状态转换尚待确认。

初次接入已有 ready Issue、重复扫描、移除/重新添加 ready、重启与中断恢复的规则尚未确定。它们不能默认复制旧博客的“只认新标签事件”合同。

## 模型配置

- 每个仓库可以分别选择默认编码模型与默认 Review 模型。
- 用户在独立 Issue 评论中通过约定格式指定模型，由程序读取并确定性解析，无需大模型理解普通讨论。
- 按角色解析：用户显式指定值优先；未指定该角色时沿用对应仓库默认值。
- 评论具体语法、可用模型列表、权限、命令编辑/冲突和运行中变更规则见 [协议草案](ISSUE_PROTOCOL.md)，尚未全部定案。

## 自动技术恢复与自身迭代

按 IS-026，已授权任务中可由模型解决的技术问题应由控制器自动组织修复，不再要求每五次返工都由人批准。显式启用 `mvp.recovery` 后，检查失败、有效 Review 拒绝、模型协议错误及未知检查故障按阶段分类；普通修复、重复失败和未知故障可进入新的只读诊断，再由程序选择修代码、重试允许的阶段或停止。诊断不能批准候选、降低门禁或扩大权限。

Issue 范围、初始 base、模型、策略和检查边界保持冻结；每次新编码后执行完整检查及新的独立 Review。有效拒绝不能靠反复 Review 原候选消除。协议纠正保留原始输出且严格解析，阶段尝试有独占证据，用量按尝试累计。未知错误不能由模型直接判通过，远端写入不确定先只读对账，不盲目重发。

工程默认的总返工、模型调用、阶段尝试及时间上限见 [自动恢复合同](AUTOMATIC_RECOVERY.md)。这些是实现安排，不是用户指定的固定参数。达到资源上限、证据完整性失败、未解决的远端写入不确定、无法消除的重复无进展，或需要新增权限和需求决策时仍停止并保留原因。

本次只通过统一审计入口迁移明确选定的 Issue #3 历史回执，验证原 Review 及确认评论，保留已用次数、原 base/模型和旧操作记录；不自动恢复所有历史任务。控制器 `07f7493` 已运行，真实 #3 经自动诊断、检查失败返工、完整检查和独立 Review 交付 Draft PR #4，见 [验收记录](VALIDATION_AUTOMATIC_RECOVERY.md)。完整 A/B 升级接棒和自动回退仍是后续范围。

## GH-5 进程看门狗

来源：项目所有者指定的 Issue #5 及本次仅限仓库代码的交付边界。宿主持久在线时，独立值守进程周期确认本服务运行器进程的宿主启动标识、PID、进程启动时间、固定运行配置、启动命令与实际安装路径；未暂停、无维护锁及身份冲突、版本指针有效、同版本预算可用且退避到期，才可从指针所指的固定安装拉起。正常和异常退出一致处理；进程仍存在时不以端口无响应或指针变更为由另启或终止。人工与值守入口共用服务级启动互斥。

维护暂停只能明确解除；同版本预算耗尽后只能明确人工恢复，切换到其他未耗尽版本可依该版本预算尝试，切回不清旧终态。未耗尽时进程持续存在达到配置时长清零本轮计数，历史证据保留。状态及审计区分本轮与历史，记每次检查、阻塞、拉起、放弃和人工操作。无人值守 GitHub 凭据必须预配置为受限文件，在运行器退出后无需操作员输入即可由值守进程注入；其他启动认证同样预配置。缺失或不可读时脱敏阻塞，不消耗启动预算。具体配置数字、路径和命令是工程参数，见 [OPERATIONS](OPERATIONS.md#看门狗维护流程待-005-交付后适用)。

看门狗不写版本指针、不作更新或回退决策，不处理任务中断、不终止存活进程、不新增远端写入。宿主故障和开机自启、看门狗自身常驻安装、卡死/业务健康判断、完整 A/B 升级接棒及通知渠道仍为后续范围。代码交付不等于已安装或实际 WD-1 无人值守凭据验收通过。
