# 外部条件等待与审计接手

来源：IS-035。用户授权区分可修复代码缺陷和缺少外部条件，建立明确停点及接手路径。具体字段和命令是工程安排；本地验证不代表真实外部验收或运行版本已切换。

## 分流规则

显式启用自动恢复的任务适用本合同；未启用恢复的兼容入口保持原有停止规则。Review 的结构化阻塞项包含 `acceptance`、`kind`、`reason`、`required_evidence`、`handoff`。`acceptance` 对应本次 Review 的不充分验收条目；`kind` 为 `code_defect` 或 `external_condition`。外部条件必须说明缺失原因、要补的证据和由谁接手。程序不从自由文本关键词猜分类。新模型输出必须带分类数组；旧 Review 没有分类字段时，保守沿用原代码返工路径。

| 反馈 | 控制器动作 |
| --- | --- |
| 全部通过 | 按原流程交付 Draft PR |
| 有代码缺陷，可能同时缺外部条件 | 保留外部依赖，先交 coder 修代码，重新完整检查与 Review |
| 仅缺外部条件 | 保存不可变候选及交接记录，进入 `awaiting_external`，停止自动编码和重复 Review |
| 分类畸形、不充分项漏分或批准与阻塞矛盾 | 严格协议纠正；不能按通过或外部等待豁免 |
| 未知检查失败 | 只读诊断可选择 `await_external` 并给出结构化条件；明确代码缺陷不能被此动作盖过 |

外部条件包括实际凭据、获准的固定安装验证环境、设备、外部服务或人必须作出的范围决定。代码错误、测试脆弱、格式和静态检查失败属于代码修复。WD-1 在离线 sandbox 中没有真实认证与恢复证据，适用外部等待；继续增加 mock 不会解除它。

## 等待与接手

等待回执保留候选 SHA、冻结 base、Issue 范围、角色模型、检查、sandbox 策略、原 Review/诊断、历史次数及用量。交接记录列出等待原因、验收条目、所需证据、接手责任和开始时间，并另存不可变文件。进入等待即结束该执行进程；已有 receipt 继续阻止自动领取重复任务。不能清空回执或重新添加 ready 绕过等待。

接手者按既有权限准备验证环境或解决缺失条件。控制器不执行交接文本中提供的命令，不自动安装候选、不读取或签发新凭据、不新增真实平台访问。证据文件必须脱敏，记录来源、过程、结果和对应候选，不包含 token 或其他秘密值。

审计续跑要求原回执字节摘要、同一候选和完整工作区、冻结范围与检查、未改 sandbox、完整前序操作链，以及每个等待验收项的新证据文件和 SHA256。完整恢复账本、用量和返工次数也与不可变交接记录核对，修改等待回执不能重获额度。证据先核验再复制到独占操作目录，独立 reviewer 只读取已保存的证据。所有原正式检查重新执行；补了证据仍可能被拒绝，不能直接 publish。

同一候选只因新增且核验过的外部证据允许再次 Review。同次提交至少一个文件摘要此前没有导入过；已经导入后仍被拒绝的证据，不能仅换路径、操作编号或验收条目措辞重复提交以碰批准。原代码拒绝不能通过此入口洗掉；候选或冻结条件发生变化必须回到适用的修复/迁移路径。

接手开始前，原回执保存在独占操作目录的 `receipt-before.json`。新检查会清除当前轮次的旧 Review 和旧反馈，避免新检查失败时误走旧拒绝路径；新的拒绝反馈同时保存操作审计项和当前轮次依据。之后同一候选因检查问题走既有审计恢复时，可以重新核验已导入证据；代码修改产生新候选后，旧候选证据不再提供给 Review。

## 预算与历史

原 `started_at`、策略额度、返工次数、Agent 尝试、用量、原拒绝和检查记录不归零。只有持久等待记录支持的实际等待时段可从活动时间扣除；候选修改、检查和模型执行仍消耗原额度。等待前活动时间或尝试次数已经耗尽时，提交外部证据不能获得新额度。需要额外额度仍走既有明确授权入口。

接手在锁后核验或复制证据阶段失败时，控制器保留原交接来源，另存新的等待起点。此次接手的执行时间仍计入活动额度，不能被下一次接手重新算作等待。无法可靠保存新停点时进入 `blocked / :mvp_external_repark_failed`，交由操作者检查审计记录。

## 本地命令

以本仓库 `mix mvp.external` 为入口。`status` 只读本地回执，不连接平台；`resume` 加载冻结工作流并核验原 Issue，调用 `Executor.resume_external/3`，不启动调度或领取其他任务。以下路径为调用占位符，不代表已执行或已安装：

```sh
mix mvp.external status /absolute/path/RECEIPT.json
mix mvp.external resume /absolute/path/WORKFLOW.md /absolute/path/RECEIPT.json /absolute/path/REQUEST.json
```

`REQUEST.json` 包含调用者明确提供的 `receipt_sha256` 与 `authorization` 对象。授权对象沿用审计字段 `id`、`authorization`（授权来源与范围说明）、`runtime_version`（操作者声明的运行代码完整提交 SHA）、`command`（操作者声明的本次调用参数列表）、`predecessor`（上次已完成操作编号或 null）、`legacy_closures`，另提供 `external_evidence`。程序校验版本和命令的格式，不将声明当作实际运行身份的证明。可选 `diagnostic` 只作为说明，不执行其中的命令。

未使用旧版检查续跑或返工扩额的任务，`legacy_closures` 为空数组；已有旧操作的首次统一审计接手，沿用原 `OperatorRecheck` 合同提供并核验完整闭合证据。已经批准并留有完整审计链的墙钟增额，从原回执恢复有效策略；外部接手不能创建新增额或改变其他策略字段。

每条 `external_evidence` 为 `{ "acceptance": "从交接记录复制的完整验收条目", "path": "/absolute/path/evidence.json", "sha256": "文件的64位小写SHA256" }`，每个不同的等待验收条目提交一个文件。同一验收条目若有多个外部条件，该文件须覆盖所有条件。文件内容应记录同一候选的验证环境、过程和结果，秘密值必须省略。程序只验证和保存提交的文件，不自动执行任何外部验收脚本。证据摘要用于绑定文件，不证明其中的结论正确；独立 Review 仍核对证据是否充分。

证据仅接受绝对路径的常规文件，不接受符号链接；单个文件最多 10 MiB，同次提交总量最多 32 MiB。复制目录和文件采用独占创建，路径冲突或复制期间文件改变会拒绝接手，已有证据不会被覆盖。

`resume` 的等待结果必须保持 `awaiting_external`，代码缺陷回修复或按原预算停止；只有完整检查与独立批准后才允许走原 Draft PR 发布路径。命令的实际验证结果见下方实施状态。

## 验收场景

- 外部条件型 Review：只进入等待，不再次调用 coder、不发布 PR；旧拒绝和完整检查保留。
- 混合 Review：代码修复优先，外部依赖仍明确可见；不能直接转等待来掩盖代码缺陷。
- 缺分类、漏条目、矛盾批准或未知分类：保守拒绝，不降低门槛。
- 错回执摘要、错候选、工作区篡改、缺证据、错文件摘要、未覆盖全部等待项、操作锁冲突：续跑拒绝且不触发模型或发布。
- 外部证据有效：保留原历史，重新全部检查，再由新的独立 Review 决定；不先编码、不自动当作验收通过。
- 等待超过原墙钟剩余：仅扣除可核验等待时段，活动执行和模型次数仍受原上限约束。
- 旧 blocked：不自动迁移、不自动续跑；首次启用新版本不重置历史或恢复旧任务。
